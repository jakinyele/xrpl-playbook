    XRPL Quick-Reference Cheat Sheet

    A condensed reference for the most common XRPL development tasks. See the Glossary for full definitions and the playbook chapters for depth.

    Table 1: Common tasks → transaction type → key fields → result codes

    Task Transaction type Key required fields Success Common failures
    Send XRP Payment Account, Destination, Amount (drops), Fee, Sequence tesSUCCESS tecNO_DST, tecUNFUNDED_PAYMENT, tecDST_TAG_NEEDED
    Send issued currency Payment + Amount as {currency, issuer, value}, trust line must exist tesSUCCESS tecPATH_DRY, tecNO_LINE, tecNO_AUTH
    Cross-currency payment Payment + SendMax, Paths (or let engine find) tesSUCCESS tecPATH_DRY, tecPATH_PARTIAL
    Place DEX offer OfferCreate TakerPays, TakerGets tesSUCCESS tecKILLED (FillOrKill), tecEXPIRED
    Cancel DEX offer OfferCancel OfferSequence tesSUCCESS tecNO_ENTRY (already gone)
    Set trust line TrustSet LimitAmount ({currency, issuer, value}) tesSUCCESS tecNO_SUITABLE_NFTOKEN_PAGE, temBAD_LIMIT
    Authorize trust line TrustSet Flags: tfSetfAuth, LimitAmount tesSUCCESS tecNO_LINE, tecNO_PERMISSION
    Set account flags AccountSet SetFlag (asf integer) or ClearFlag tesSUCCESS temINVALID_FLAG, tecNO_SUITABLE_NFTOKEN_PAGE
    Set regular key SetRegularKey RegularKey (or omit to remove) tesSUCCESS temBAD_REGKEY, tecNO_ALTERNATIVE_KEY
    Add/update signer list SignerListSet SignerQuorum, SignerEntries tesSUCCESS temBAD_SIGNER, tecNO_ALTERNATIVE_KEY
    Create escrow EscrowCreate Destination, Amount, FinishAfter or Condition tesSUCCESS tecNO_DST, tecINSUF_RESERVE_LINE
    Finish escrow EscrowFinish Owner, OfferSequence, Condition/Fulfillment tesSUCCESS tecNO_TARGET, tecCRYPTO_CONDITION_FAILURE
    Create payment channel PaymentChannelCreate Destination, Amount, SettleDelay, PublicKey tesSUCCESS tecNO_DST, tecUNFUNDED
    Claim payment channel PaymentChannelClaim Channel, Balance (cumulative), Signature tesSUCCESS tecNO_TARGET, tecBAD_SIGNATURE
    Issue MPT MPTokenIssuanceCreate MaximumAmount, AssetScale, Flags (tfMPT*) tesSUCCESS temDISABLED (amendment not active)
    Mint NFT NFTokenMint NFTokenTaxon, Flags (tfTransferable, etc.) tesSUCCESS tecINSUFFICIENT_RESERVE
    Create AMM pool AMMCreate Amount (asset1), Amount2 (asset2), TradingFee tesSUCCESS tecUNFUNDED, temBAD_AMM_TOKENS
    Deposit AMM liquidity AMMDeposit Asset, Asset2, Amount and/or Amount2, Flags tesSUCCESS tecAMM_BALANCE, temBAD_AMM_TOKENS
    Set price oracle PriceOracleSet OracleDocumentID, PriceDataSeries, LastUpdateTime tesSUCCESS temDISABLED (amendment not active)

    Table 2: Result code families — fee and ledger behavior

    Prefix Meaning Fee charged? Reaches validated ledger? Recovery action
    tes Success ✅ Yes ✅ Yes None needed
    tec Claim (partial failure) ✅ Yes ✅ Yes Fix the root cause; rebuild + resubmit
    ter Retry ❌ No ❌ No Resubmit after a moment (transient condition)
    tef Failure ❌ No ❌ No Fix the issue (bad sequence, bad sig); rebuild
    tem Malformed ❌ No ❌ No Fix the transaction structure; rebuild
    tel Local ❌ No ❌ No Transient node load issue; retry or use different node

    Critical tec codes every payment flow must handle:

    Code Value Meaning
    tecNO_DST 124 Destination account does not exist
    tecNO_DST_INSUF_XRP 125 Destination exists but balance below reserve
    tecUNFUNDED_PAYMENT 104 Sender has insufficient XRP/IOU balance
    tecPATH_DRY 128 No path with sufficient liquidity
    tecPATH_PARTIAL 101 Partial fill only; tfPartialPayment not set
    tecDST_TAG_NEEDED 143 Destination requires a destination tag

    Critical tef codes (sequence management):

    Code Value Meaning
    tefPAST_SEQ -168 Sequence already consumed; fetch and update
    tefALREADY -198 Exact same tx already in the ledger

    Table 3: Reserve cost reference

    Reserves are denominated in XRP drops. Fetch live values via: 

    { "command": "server_info" }
→ result.info.validated_ledger.reserve_base_xrp   (base reserve)
→ result.info.validated_ledger.reserve_inc_xrp    (per-object increment)

    Or via fee command: 

    { "command": "fee" }
→ result.drops.base_fee
→ result.drops.minimum_fee

    Current values (subject to fee voting):

    Reserve type Current value Formula
    Base account reserve 2 XRP Fixed per account
    Owner reserve (per object) 0.2 XRP reserve_inc × owner_count

    Common object costs:

    Object type Owner reserve
    Trust line (RippleState) 0.2 XRP
    DEX offer (Offer) 0.2 XRP
    Escrow (Escrow) 0.2 XRP
    Payment channel (PayChannel) 0.2 XRP
    Signer list (SignerList) 0.2 XRP × (N+1) where N = number of signers
    NFT page (NFTokenPage) 0.2 XRP per page (up to 32 NFTs per page)
    MPT holder entry (MPToken) 0.2 XRP
    Price oracle (PriceOracle) 0.2 XRP
    Check (Check) 0.2 XRP
    Ticket (Ticket) 0.2 XRP each

    Reserve calculation example: 

    Account with: 3-of-5 SignerList + 10 trust lines + 5 open offers + 2 escrows
= 2 XRP (base)
+ (5+1) × 0.2 XRP (signer list)
+ 10 × 0.2 XRP (trust lines)
+ 5 × 0.2 XRP (offers)
+ 2 × 0.2 XRP (escrows)
= 2 + 1.2 + 2.0 + 1.0 + 0.4 = 6.6 XRP locked

    The account needs 6.6 XRP + safety_buffer to remain able to submit transactions. Spendable XRP = balance − 6.6 XRP. If spendable drops to 0, the account cannot pay fees.

    See Glossary for full definitions. See ch01 › Payments for submission gotchas.
