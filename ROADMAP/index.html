    Roadmap

    This roadmap describes the planned evolution of the XRPL Playbook. It is a living document — priorities will shift as the XRP Ledger and its ecosystem evolve. See CONTRIBUTING.md if you'd like to help.

    Guiding principles

    • Production-first. Every chapter targets real, deployable systems — not toy examples.
    • Decisions over recipes. Explain the trade-offs so readers can make their own informed choices.
    • Safety by default. Security, compliance, and operational concerns are treated as first-class, not afterthoughts.
    • Current and accurate. Content tracks the live protocol and is revised as amendments ship.

    Phase 0 — Coming from other chains → ch00-coming-from-other-chains

    • [x] Chapter-level README — an optional on-ramp for engineers arriving from EVM, Solana, or Bitcoin; the four mappings that matter most (no smart contracts → native primitives; failure is usually free and off-ledger; state costs a refundable reserve; fees burn), and pointers into the chapter each topic is covered in depth.
    • [x] Concept Mapping (ch00-coming-from-other-chains/concept-mapping) — side-by-side translation tables (account/execution model; tokens & value; failure, finality & programmability) with a Watch out note on every lossy analogy. XRPL-side claims source-anchored to rippled/: account-based AccountRoot/sfSequence and ltTICKET; tec-vs-EVM-revert semantics ("claim fee to use the sequence number", TER.h); trust lines (ltRIPPLE_STATE) vs ERC-20; native ltOFFER/ltAMM/ltMPTOKEN*/ ltNFTOKEN_PAGE objects vs deployed contracts; amendments vs contract upgrades. Cross-linked to ch01–ch06.
    • [x] RPC Method Mapping (ch00-coming-from-other-chains/rpc-method-mapping) — the day-one API lookup mapping EVM/Solana JSON-RPC calls to XRPL command equivalents (eth_getBalance→account_info/account_lines, eth_call→ledger_entry/ripple_path_find, eth_sendRawTransaction→submit, eth_getTransactionReceipt→tx, eth_estimateGas→fee), each pinned to the canonical command dispatch table (src/xrpld/rpc/detail/Handler.cpp) with Watch out notes.
    • [x] Indexing (History & State) (ch00-coming-from-other-chains/indexing-and-history) — the TheGraph/Etherscan/eth_getLogs replacement: account_tx pagination (ledger_index_min/max -1 sentinels, forward, binary, the opaque {ledger, seq} marker, the 10/200/400 limit envelope from Tuning.h), the Clio read-replica vs validating-node split, and state indexing via ledger_data (type filtering, hex-key marker, kBinaryPageLength = 2048 / kJsonPageLength = 256 from Tuning.h, source-anchored to LedgerData.cpp). Dual comparison tables: mental-model contrast (query unit, scope, use case) and parameter-level reference (pagination cursor type, limit, forward).
    • [x] Subscriptions & the Event Model (ch00-coming-from-other-chains/subscriptions) — the logs/topics/webhooks replacement: the subscribe streams, accounts/accounts_proposed, and books feeds, with the exact message type each publisher emits (ledgerClosed, transaction, validationReceived, …) from NetworkOPs.cpp, and the validated-gated finality + reconnect/backfill pattern.
